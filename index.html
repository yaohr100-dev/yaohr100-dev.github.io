Deep DivesExplore the Details

Using five seasons of play-by-play data and EPM (Estimated Plus-Minus), advanced analytics can answer one question: how many wins does a single player really add — stripped of teammate luck, opponent strength, and random noise.

1. How to Scrape the Data

Data sources:

  • NBA.com Stats API — official play-by-play, box scores, tracking data
  • Basketball-Reference — clean historical tables, PER, BPM, VORP
  • Dunks & Threes — EPM, Estimated Skills, and methodology
  • pbpstats.com — processed play-by-play, lineup data

Scraping tools: Python + requests / httpx · BeautifulSoup / lxml · Selenium / Playwright · nba_api library

2. How to Clean the Data

Manual (understand first): Excel / Google Sheets for single-season inspection · Hand-label player name mappings · VLOOKUP joins to validate logic before coding.

Automated (scale up): Pandas (.merge(), .dropna(), .groupby()) · DuckDB / SQL for RAM-heavy datasets · OpenRefine for name normalization.

3. Modeling & Algorithms

SPM — Statistics Plus-Minus

Raw plus-minus fluctuates wildly year to year. Adding box-score statistics into the regression makes SPM far more stable. The most recent season carries weight ×0.50, second-to-last ×0.33, and three years ago ×0.17. Rookies default to SPM = −2.16.

The 2007-08 Celtics were projected to win 67.5 games via SPM alone; they won 66. Average error across all teams: 4.5 wins — beating the Pythagorean formula. (Source)

APM — Adjusted Plus-Minus

A regression model where each 10-man lineup segment is one row, and every player is a variable. It asks: "holding the other nine players constant, how many points per 100 possessions does this player add?" The fatal flaw is overfitting — small-sample performances can produce extreme ratings.

RAPM — Regularized Adjusted Plus-Minus

Ridge regression (L2 regularization) pulls extreme values back unless the evidence is overwhelming. Cross-validation chooses λ — the penalty strength. Multi-year RAPM stacks seasons with exponential decay weighting for 5,000+ possessions of data per player. (Sill's original paper)

EPM — Estimated Plus-Minus

The synthesis: SPM provides a stable box-score prior; RAPM adjusts it with on/off-court evidence. This Bayesian framework produces the most robust single-number public metric. Estimated Wins are then computed by aggregating each player's EPM across minutes, converting point differential to win probability via the Pythagorean formula.

Estimated Skills & DARKO (Kalman Filter)

If a player shoots 60% from three over 10 games, is that real? Estimated Skills applies a Kalman filter — the same algorithm used in rocket navigation — to every skill dimension. DARKO adds exponential decay weighting, age curves, rest-advantage, and opponent strength. It predicts forward: "what will this player do tomorrow?"

Research project supervised by MIT Professor Gunther Roland · Jul–Oct 2024.

1. Motivation

Cosmic muons are produced when high-energy cosmic rays hit the upper atmosphere. Atmospheric pressure acts as a shield — higher pressure means more air, so more muons decay before reaching detectors. Quantifying this relationship lets us correct for weather effects and sharpen sensitivity to rare cosmic events like high-energy particle bursts.

2. What I Did

Task 1 — Atmospheric Pressure vs. Time-Stamp. Used Matplotlib + Pandas to generate pressure-over-time plots for each data group. Manually classified each plot — identifying sensor drift, diurnal cycles, and anomalous spikes. Building intuition for "normal" detector behavior made automated classification possible later.

Task 2 — Diurnal Pressure Visualization. Built a 24-hour heatmap in Python showing how atmospheric pressure varies across hours of the day. Revealed a clear diurnal pattern: muon rates were lower during midday (warmer, less dense air) and higher at night (cooler, denser air). Quantifying this cycle let us subtract it out and isolate pressure-driven effects.

Task 3 — Coincident Event Rate Calculation. Cosmic Watch uses two scintillator panels — a true muon event requires both to trigger within a narrow time window. In Excel, calculated coincident event rates and false-coincidence backgrounds. Fed into time-difference calibration to correct a systematic offset, improving sensitivity to rare events.

Task 4 — Team Synthesis & Final Figures. Consolidated all key visualizations into a unified presentation with consistent styling and explanatory captions.

3. Results

📉
Pressure vs. Muon Rate (Anti-Correlation)

Higher pressure = denser air = more muons decay before reaching ground level. Confirms theoretical expectation. Enables weather-artifact correction in real-time monitoring.

⏱️
Improved Timing Calibration

Refined time-difference calibration eliminates systematic offset, enhancing sensitivity to rare cosmic phenomena including high-energy particle bursts.

4. Challenges & Lessons

⚡ The noise problem. Raw detector data is noisy — electrical interference, temperature drift, random coincidences all mimic real muons. Distinguishing signal from noise required iterative filtering: threshold cut → statistical test → visualize → refine. Data cleaning is a loop, not a one-pass operation.

🔄 Manual classification as a forcing function. Classifying hundreds of plots by hand felt tedious, but forced deep understanding of the data's texture — drift patterns, diurnal cycles, the difference between a pressure anomaly and a loose cable.

🔗 Connection to NBA Analysis. Both projects boil down to separating signal from noise. Atmospheric pressure confounds muon detection just like teammate quality confounds raw plus-minus. Ridge regression in RAPM is conceptually identical to the regularization applied to time-difference distributions. Different domains, same logic: control for what you can measure, regularize against what you cannot.
